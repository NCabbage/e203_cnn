## 一、设计（最小改动、零风险）

复用 `CFG1` 的空闲位 **[20]** 作为池化开关，MAC 处把"累加"换成"取最大"：

```verilog
acc <= cfg_pool ? ((acc > pool_max32) ? acc : pool_max32)   // 池化：取最大
                : (acc + acc_sum);                          // 卷积：累加
```

配置成 `K=2, STRIDE=2, SHIFT=0, RELU=0, POOL=1` 就是标准 2×2 max pooling。
`cfg_pool=0` 时路径与原来完全一致（回归实测 cycles 一个没变）。

池化模式的三个要点：
1. `bias` 硬件置 0（池化不应叠加偏置）
2. `acc` 初值取 `-32'sd128`（int8 最小值），避免全负窗口被 0 污染
3. 无效 lane（padding 越界）按 `8'sh80`（-128）参与 max，不参与则不改变结果

## 四、综合与实现（PYNQ-Z2 / xc7z020clg400-1）

| 项 | 加池化前 | 加池化后 | 增量 |
|---|---:|---:|---:|
| Slice LUTs | 15,806 (29.71%) | **15,904 (29.89%)** | +98 (+0.18 pp) |
| Slice Registers | 10,229 (9.61%) | 10,237 (9.62%) | +8 |
| Block RAM | 49 (35.00%) | 49 (35.00%) | 0 |
| DSP | 16 | 16 | 0 |
| WNS / WHS | 0.000 / 0.023 | **0.000 / 0.028** | 时序满足 |

结论：池化只多花 **98 个 LUT + 8 个 FF**，BRAM/DSP 零增加，时序仍然收敛。

## 五、使用方法

```c
/* 2x2 max pooling：H×W×1 -> (H/2)×(W/2)×1 */
CNN_WR(CNN_CFG0, cnn_cfg0(H, W, 1, 2));              /* C=1, K=2 */
CNN_WR(CNN_CFG1, cnn_cfg1(1, 2, 0, 0, 0) | (1u << 20));  /* OC=1, S=2, POOL=1 */
cnn_load_input(x, H * W);
cnn_run();
for (int i = 0; i < (H/2)*(W/2); i++) y[i] = cnn_read_output(i);
```

多通道池化：逐通道调用（每次 `C=1`），因为硬件一次只处理单通道的 K×K 窗口。
