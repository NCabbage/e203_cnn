## 一、结论先看

两项**都不需要新增 RTL 逻辑**——现有 `cnn_top` 已经支持：

| 项 | 用到的形态 | 此前是否已验证 |
|---|---|---|
| FC 硬件复用 | `H=W=1, K=1, C=输入维, OC=类数` | 是（LeNet 的 OUT 层一直这么跑） |
| Sobel 边缘检测 | `K=3, C=1, OC=2`（Gx/Gy 双核） | 是（与 `t4_multi` 同形态） |

唯一改动是把 Sobel 的两个核**加进权重 ROM**（多了 6 个字）。

## 二、FC = 1×1 卷积

`cnn_top` 在 `K=1` 时走 `tap_next` 的退化路径（只在 `c` 上推进），所以
`H=W=1, K=1, C=8, OC=4` 就是一次 8→4 的全连接。

**仿真用例 `t9_fc`**：同一份数据分别用 `golden_fc.fc_int8()`（矩阵形式）和
`conv2d_int8()`（1×1 卷积形式）计算，结果完全一致：

```text
FC(8->4) 与 1x1 conv 结果一致: [-15, -16, -1, 30]
t9_fc PASS (18 cycles)
```

**LeNet 里的实际使用**：最后一层 F6(84) → OUT(10) 就是按 `H=W=1, K=1, C=84, OC=10` 跑的，
属于本次"FC 硬件复用"的直接实证。

## 三、Sobel 边缘检测（双核）

两个 3×3 核装进 ROM 的两个输出通道：

```text
Gx = [-1  0  1]      Gy = [-1 -2 -1]
     [-2  0  2]           [ 0  0  0]
     [-1  0  1]           [ 1  2  1]
```

ROM 新增段：`W_BASE_SOBEL = 11060`，`num_tap_groups=3, OC=2`，占 6 个字。
`W_TOTAL_WORDS` 由 `11060` 改为 `11066`。

**仿真用例 `t10_sobel`**：8×8 输入（中间 4×4 方块 + 右上角负区域），输出 6×6×2。

```text
t10_sobel PASS (362 cycles)

Gx（垂直边缘）:              Gy（水平边缘）:
 30  30   0   0 -120 -120      30  90 120 120 120 120
 90  90   0   0 -120 -120      30  90 120 120 120 120
120 120   0   0 -120 -120       0   0   0   0   0   0
120 120   0   0 -120 -120       0   0   0   0   0   0
 90  90   0   0  -90  -90     -30 -90-120-120 -90 -30
 30  30   0   0  -30  -30     -30 -90-120-120 -90 -30
```

方块左边界在 Gx 上呈正响应、右边界负响应；上边界在 Gy 上正、下边界负——
正是标准 Sobel 行为。方块内部（Gx 中间两列、Gy 中间两行）全 0，说明没有伪边缘。

## 附录：一个踩过的坑（2026-10-16）

**现象**：Sobel 仿真 PASS，上板 Gx/Gy 全 0、`SOBEL SELFTEST: FAIL`。

**根因**：ROM 内容没更新到 Vivado 实际读取的位置。

`rtl/cnn/cnn_top.v` 里：

```verilog
initial $readmemh("rom_all_tap.hex", w_rom);
```

Vivado 综合时按"当前工作目录 → RTL 源文件目录"的顺序找这个文件。而 `launch_runs synth_1`
会先把 `synth_1` 目录整个清空（`reset_run`），所以只有放在 **`e203_zynq\rtl\cnn\`**
（RTL 同目录）的那一份才是稳定生效的。

当时只同步了工程根目录和 `synth_1`/`impl_1`，**漏了 `rtl\cnn\`**，于是 Vivado 读到了
10-11 留下的 11060 行旧文件：ROM 只有 LeNet 权重，Sobel 段（11060–11065）读出全 0，
`acc = 0` → 输出全 0。

**关键判据**：综合日志里是

```text
INFO: [Synth 8-3876] $readmem data file 'rom_all_tap.hex' is read successfully [...../rtl/cnn/cnn_top.v:84]
Parameter W_TOTAL_WORDS bound to: 11066
```

"read successfully" **不代表读到了对的文件**——它只说明读到了某个同名文件。

**修复**：`rom_all_tap.hex` 必须同步到所有会被搜索的位置，重点是 `rtl\cnn\`：

```text
board工程\rtl\cnn\        ← 最重要（$readmemh 实际来源）
board工程\                （根目录）
board工程\prj\...\synth_1\  impl_1\   （会被 reset 清掉，仅作备份）
sim\run\  sim\run_w3\  sim\bram_check\   （仿真用）
```

**通用教训**：凡是 `$readmemh` 依赖的数据文件，"生成新版本"之后必须确认
**Vivado 实际读到的那一份**也更新了；否则仿真全过、上板全错。
