## 三、CNN 外设的地址（B 必须知道）

`e203_subsys_mems.v` 里的 ICB 分叉器地址表（第 121~157 行）：

| 端口 | 地址范围 | 用途 |
|---|---|---|
| O0 | 0x0000_0000 - 0x0000_0FFF | Debug Module |
| O1 | 0x0000_1000 - 0x0000_1FFF | MROM |
| O2 | 0x0002_0000 | 未用 |
| O3 | 0x2000_0000 - 0x3FFF_FFFF | QSPI0-RO |
| O4 | 0x8000_0000 - 0xFFFF_FFFF | SysMem（ITCM/DTCM 等） |
| **O5** | **0x4000_0000 - 0x4FFF_FFFF** | **← 外挂 AXI 外设，CNN 就挂这里** |
| O6/O7 | - | 未用 |

所以：

- CPU 侧基址 = **`0x4000_0000`**，跨 256 MB 的区域（REGION_LSB=28）
- 你之后写驱动就是 `*(volatile uint32_t*)(0x40000000 + offset)`
- 你在 `regfile.v` 里用的 `wr_addr[5:2]` 正好是 16 个字 = 0x40 字节的寄存器空间，
  即偏移 0x00~0x3C，和基址组合后是 0x4000_0000 ~ 0x4000_003C

## 四、移植前必读

**同学的桥目前有硬死锁，读写不通（详见 03 号文档）**，原因是：
E203 的 `sirv_gnrl_icb2axi` 用的是"holdup 让行"时序 ——
AWVALID 要等 WREADY、WVALID 要等 AWREADY；
而同学的从机又要求"AWVALID 和 WVALID 同时有效"才给 AWREADY/WREADY。
两边互相等 → 永远卡死。

原厂示例从机 `sirv_expl_axi_slv` 的写法是 `assign axi_awready = 1'b1;`（常高），
就是为绕开这个坑。修复方向见 03 号文档。
