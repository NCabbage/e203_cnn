# 第二部分：接口契约（B 承诺提供、A 遵守使用）

## 1. 端口契约（最硬的一条 —— 分界线就在这 8 个信号）

```
module cnn_regs #(parameter AW=32, DW=32) (
    input  wire              clk,        // 与 AXI-Lite 从机同一个时钟
    input  wire              rst_n,      // 与从机同一个复位（低有效）
    input  wire              wr_en,      // 1 拍写脉冲
    input  wire [AW-1:0]     wr_addr,    // 写地址（用低 8 位译码）
    input  wire [DW-1:0]     wr_data,    // 写数据
    input  wire [(DW/8)-1:0] wr_mask,    // 字节掩码
    input  wire [AW-1:0]     rd_addr,    // 组合读地址
    output reg  [DW-1:0]     rd_data     // 组合读数据
);
```

**B 承诺**：这组端口**不会再变**。你要改寄存器行为，改的是 `cnn_regs.v` 内部的
`case (wa)` 分支，端口不动 —— 不动就影响不到你的从机。

**你要做的**：只把从机的 `o_ctrl_*` 接到上面这组信号，别的都不用管。

## 2. 寄存器映射（冻结版）

**基址 `0x4000_0000`**（`e203_subsys_mems.v` 里 ICB 分叉的 O5 端口，窗口 0x4000_0000–0x4FFF_FFFF）

| 偏移 | 名字 | 读写 | 位定义 |
|---|---|---|---|
| 0x00 | CTRL | W | [0]start [1]clr_wptr [2]clr_iptr [3]clr_bptr |
| 0x04 | STATUS | R | [0]busy [1]done |
| 0x08 | WDATA | W | 写一个 int8 权重 → w_mem[wptr++]（低 8 位有效） |
| 0x0C | IDATA | W | 写一个 int8 激活 → x_mem[iptr++] |
| 0x10 | BIAS | W | 写一个 int32 偏置 → b_mem[bptr++] |
| 0x14 | CFG0 | W | H[7:0] W[15:8] C[23:16] K[31:24] |
| 0x18 | CFG1 | W | OC[7:0] STRIDE[9:8] PAD[13:10] SHIFT[18:14] RELU[19] |
| 0x1C | OINDEX | W | 设置要读的输出序号 |
| 0x20 | ODATA | R | 读 y[OINDEX]（int8 符号扩展到 32 位） |
| 0x24 | WPTR | R | 权重写指针（调试） |
| 0x28 | IPTR | R | 输入写指针（调试） |
| 0x2C | YCOUNT | R | 已完成输出个数 |
| 0x30 | VERSION | R | 固定 `0x0001_0000`（联调第一件事就是读它） |

## 3. 数值约定（三方必须一致：RTL / Python / 你的 C）

```
激活 int8 有符号, 权重 int8 有符号, 偏置 int32, 累加 int32
y = (Σ x·w + bias) >>> SHIFT      ← 算术右移（RTL 里就是 >>>）
y = max(y, 0)                     ← ReLU，在右移之后
y = clamp(y, -128, 127)           ← 饱和到 int8
```

## 4. 数据布局（写数据顺序）

```
激活 x : [H][W][C]           地址 = (h*W + w)*C + c
权重 w : [K][K][C][OC]       地址 = ((kh*K + kw)*C + c)*OC + oc
输出 y : [OH][OW][OC]        读序号 = ((oh*OW) + ow)*OC + oc
其中 OH = (H + 2*PAD - K)/STRIDE + 1，OW 同理
```

## 5. `cnn.h`（可直接抄）

```c
#ifndef __CNN_H__
#define __CNN_H__
#include <stdint.h>

#define CNN_BASE     0x40000000UL
#define CNN_CTRL     (CNN_BASE + 0x00)
#define CNN_STATUS   (CNN_BASE + 0x04)
#define CNN_WDATA    (CNN_BASE + 0x08)
#define CNN_IDATA    (CNN_BASE + 0x0C)
#define CNN_BIAS     (CNN_BASE + 0x10)
#define CNN_CFG0     (CNN_BASE + 0x14)
#define CNN_CFG1     (CNN_BASE + 0x18)
#define CNN_OINDEX   (CNN_BASE + 0x1C)
#define CNN_ODATA    (CNN_BASE + 0x20)
#define CNN_WPTR     (CNN_BASE + 0x24)
#define CNN_IPTR     (CNN_BASE + 0x28)
#define CNN_YCOUNT   (CNN_BASE + 0x2C)
#define CNN_VERSION  (CNN_BASE + 0x30)

#define CNN_CTRL_START     (1u<<0)
#define CNN_CTRL_CLR_WPTR  (1u<<1)
#define CNN_CTRL_CLR_IPTR  (1u<<2)
#define CNN_CTRL_CLR_BPTR  (1u<<3)
#define CNN_STATUS_BUSY    (1u<<0)
#define CNN_STATUS_DONE    (1u<<1)

#define CNN_RD(a)   (*(volatile uint32_t *)(a))
#define CNN_WR(a,v) do { (*(volatile uint32_t *)(a)) = (uint32_t)(v); } while (0)

static inline uint32_t cnn_cfg0(uint32_t h,uint32_t w,uint32_t c,uint32_t k){
    return (h&0xFF) | ((w&0xFF)<<8) | ((c&0xFF)<<16) | ((k&0xFF)<<24);
}
static inline uint32_t cnn_cfg1(uint32_t oc,uint32_t stride,uint32_t pad,uint32_t shift,uint32_t relu){
    return (oc&0xFF) | ((stride&3u)<<8) | ((pad&0xFu)<<10) | ((shift&0x1Fu)<<14) | ((relu&1u)<<19);
}
#endif
```

## 6. 驱动时序（照这个顺序，别改）

```
1) 读 VERSION，应 == 0x00010000        ← 第一件事，判断桥通没通
2) 写 CTRL = 0x0E                       ← 清 wptr/iptr/bptr
3) 写 CFG0 = cnn_cfg0(H,W,C,K)
   写 CFG1 = cnn_cfg1(OC,STRIDE,PAD,SHIFT,RELU)
4) 循环写 IDATA  (H*W*C 个)              ← 自动递增
   循环写 WDATA  (K*K*C*OC 个)
   循环写 BIAS   (OC 个)
5) 写 CTRL = 0x01                       ← start
6) 轮询 STATUS 直到 done==1（带超时）
7) 循环 { 写 OINDEX=k; 读 ODATA }        ← 先写序号再读数据
8) 写 CTRL = 0                          ← 必须！否则内核停在 DONE 回不去 IDLE
```

**两个容易踩的点**：
- 读结果是**两步**（写 OINDEX → 读 ODATA），不是自动递增
- 每轮结束**必须写 CTRL=0**，否则下一轮启动不了

## 9. 出问题怎么找我（排查顺序）

| 现象 | 先查什么 |
|---|---|
| 读 VERSION 不是 `0x00010000` | 桥有没有接对（`expl_axi_*` 那组信号）、地址是不是 `0x4000_0000` |
| 读任何寄存器都是 `0xDEADBEEF` | `rd_addr` 译码没对（地址低 8 位）、或读地址接错了 |
| STATUS 一直是 0（既不 busy 也不 done） | `cnn_start` 没接上（CTRL 写没生效） |
| 写完数据 WPTR/IPTR 不涨 | `wr_en` 没接、或 `wr_addr` 低 8 位不对 |
| done 一直不来 | CFG 配错了（K > H 或 W 会导致无输出） |
| 结果不对但 done 正常 | 数据布局（x/w 的顺序）或数值约定（shift/relu）对不上 |
| 仿真过、上板不过 | 时钟/复位接法；或字节掩码（你的 `mask_data` latch —— 但那个已不在通路上） |

**最快的定位手段**：像我一样用 JTAG/GDB 直接读写寄存器（
`x/1xw 0x40000030`、`set {unsigned int}0x40000000 = 0xE`），
绕开 C 代码，先确认硬件通路本身是好的。

### 10.4 A 的 C 实现必须遵守的（对着黄金模型核）

- [ ] 输入/权重用 `int8_t`（**有符号**，不是 uint8）
- [ ] 累加器用 **`int32_t`**，中途不要截断成 int16
- [ ] 右移：`acc >> shift`（**变量类型必须是有符号** —— C 的有符号右移 = 算术右移，
      和无符号右移结果完全不同；黄金模型里对应 `>>>`）
- [ ] **ReLU 在右移之后**（顺序错了结果就不一样）
- [ ] 输出饱和到 `[-128, 127]`
- [ ] 输出顺序 `((oh*OW)+ow)*OC + oc`（`oc` 最内层）

### 10.5 A 怎么自测（三步，越早越好）

1. **PC 上先跑**：把 `golden.txt` 里的输入/权重抄成数组，跑你的 C 卷积，
   和同一文件里的期望输出比 → **纯软件就验证掉**
2. **上板再跑**：同样的数据下到板子上，串口打印，和 `golden.txt` 比
3. **和 RTL 比**：硬件加速器的输出（读 ODATA）也要和它一致 → **三方对齐才算通**

> 第 1 步在 PC 上就能做完，**不占板子**，这是最省时间的验证顺序。

### 10.6 一句话

> **黄金模型不是"参考资料"，是"验收标准"。**
> 你的 C 卷积、B 的 RTL、板上的硬件，三者的输出必须逐点相等 ——
> 而"相等"的定义就写在 `int8_conv.py` 里。
