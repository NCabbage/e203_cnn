## 一、总原则：芯片相同 -> 逻辑结论互通；只有 4 处板级差异

两颗板子**同一颗 FPGA**，所以：

| 结论类别 | 能不能互通 |
|---|---|
| CNN / 桥 / 寄存器组的 RTL 功能与仿真 | ✅ 完全互通 |
| 资源占用（LUT/FF/DSP/BRAM） | ✅ 互通（PLL IP 不同会差个 MMCM/PLL，可忽略） |
| 时序（WNS/最高频率） | ✅ 互通（两边内核都是 16 MHz） |
| 引脚约束 / 时钟源 / 复位极性 / 下载与串口通路 | ❌ **各写各的，不许互相覆盖** |

## 二、两板对照表

| 项 | PYNQ-Z2（我） | 征服者7020（同学） | 影响共用 RTL？ |
|---|---|---|---|
| FPGA | XC7Z020-1CLG400C | XC7Z020-1CLG400C | 否 |
| PL 输入时钟 | **H16 = 125 MHz**（以太网 PHY 的 CLK125） | **H16 = 50 MHz**（板上晶振，period 20ns） | ⚠️ 影响 PLL **IP 配置**，不影响 RTL 逻辑 |
| 内核时钟 | PLL_1 (PLLE2) 125MHz -> **16.000 MHz** | PLL (MMCM) 50MHz -> **16 MHz** | 否（都是 16 MHz） |
| RTC/低频 | 8.421 MHz /256 -> 32.89 kHz | 同左（同一条链） | 否 |
| **复位按键** | **D19，按下=高** -> `assign ck_rst = ~mcu_rst;` | **H17，按下=低** -> `assign ck_rst = mcu_rst;` | ❌ **必须各自保留** |
| JTAG 引脚 | W18(TCK)/W19(TDO)/V6(TMS)/U7(TDI) | M17/J19/F19/D19 | ❌ XDC 各一份 |
| 下载器 | 外接 FT2232 "Dual RS232"（板载 TUL 只连 PS，碰不到 E203） | 板载 JTAG | ❌ 下载流程各一份 |
| UART | V7/U8 -> 外接 FT2232 通道B（COM7, 115200） | B20/B19 | ❌ |
| 用户 LED | R14/P14/N16/M14 | L17/H18/N17/P15 | ❌ 例程要分开写 |

> 复位极性是**最典型的板差异**：
> 同学那份 `aic_rv32.v` 写的是 `ck_rst = mcu_rst`（在他们板上对，因为按键按下=低）；
> 我这边必须写成 `~mcu_rst`（我板按键按下=高）。
> **这一行谁抄谁，谁就板子起不来。**

## 三、目录边界：共用区 / 板专属区

### 共用区（两人必须保持一致，改动要通知对方）
```
rtl/core, rtl/subsys, rtl/perips, rtl/general, rtl/debug, rtl/mems, rtl/fab
rtl/axi_lite_slave/     <- A 的桥
rtl/cnn/                <- B 的 CNN 加速器
sw/                     <- SDK 工程、C 驱动、寄存器头文件
sim/                    <- testbench、一键回归
python/                 <- 黄金模型、测试向量
report/                 <- 框图、指标、波形
```

### 板专属区（**各留一份，永不互相覆盖**）
```
board/pynqz2/   aic_rv32.v  +  E203_PYNQZ2.xdc   +  PLL_1 的 .xci
board/ax7020/   aic_rv32.v  +  E203_AX7020.xdc   +  PLL   的 .xci
```

**注意：连 PLL 的 `.xci` 都算板专属**（一个按 125 MHz 输入配、一个按 50 MHz 输入配，
输出都凑到 16 MHz）。共用区里只允许出现"例化 PLL、用它的 16 MHz 输出"这件事，
不许把 .xci 传来传去。

## 四、每次提交前的 3 问自检

1. **我改的文件在共用区吗？** 如果是 —— 里面有没有出现：
   引脚名（H16/W18/D19…）、板名（PYNQ/AX7020）、时钟频率常数（125/50）、
   按键极性（mcu_rst 直接当复位用）？出现任何一个就是违规。
2. **这块逻辑会因时钟源不同而行为不同吗？**
   两边内核都是 16 MHz -> 不会。若哪天有人改了内核频率，两边**必须同步改**。
3. **对面板子怎么验证？** 写清对面板的：烧 bit 命令、下载命令、串口口名。
   只写自己的 = 没写完。

## 六、两份 `aic_rv32.v` 的确切差异（只有 4 条，抄代码时对着看）

| # | PYNQ-Z2 | AX7020 | 要不要合并 |
|---|---|---|---|
| 1 | `assign ck_rst = ~mcu_rst;` | `assign ck_rst = mcu_rst;` | ❌ 各留各的 |
| 2 | 有 `IBUFG clk_ibufg_inst`，PLL 接 `clk_bufg` | 没有，PLL 直接接 `clk` | ❌ 各留各的 |
| 3 | `.hfxoscen(1'b1)` / `.lfxoscen(1'b1)` | `.hfxoscen()` / `.lfxoscen()`（悬空） | ✅ **可以统一**（建议都接 1'b1） |
| 4 | 无 | 多一个 `ila_0` 实例（探 gpioA_17） | ❌ 调试用，各留各的 |

> 第 3 条是唯一值得统一的：建议同学的 AX7020 也把 `hfxoscen/lfxoscen` 接 1'b1，
> 这样两边共用区行为一致。

## 七、CNN 这块的"板无关"要求（B 自己的约束）

B 写的 CNN RTL 必须满足：

1. **不出现任何引脚/板名/频率常数**；时钟只从端口 `clk` 进来
2. **不直接驱动 LED/按键** —— 需要指示就输出端口，由各自顶层去接
3. 只用 `0x4000_0000` 这个 **SoC 内部地址**（板无关，两边一致）
4. testbench 不许依赖板级文件；测试向量（hex）两边共用同一份
5. 上板验证写成两份：
   - PYNQ-Z2：`program_fpga.bat` -> `run_e203.bat` -> COM7
   - AX7020 ：（同学补：烧 bit + 下载 + 串口口名）
